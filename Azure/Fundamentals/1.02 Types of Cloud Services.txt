TYPES OF CLOUD SERVICES
========================================

THE LAYERS OF A CLOUD ENVIRONMENT
----------------------------------------
Physical Datacenter: The actual building/facility where the cloud
provider's servers and networking equipment are located.

Physical Network: Physical networking equipment such as cables,
switches, and routers that connect the servers.

Physical Hosts: Physical servers that provide the actual computing
power.

Network Controls: Logical network components such as firewalls,
security rules, and network configurations.

Operating System (OS): Software such as Windows or Linux that manages
the computer's hardware and provides an environment for applications
to run.

Applications: Software/programs that perform tasks for the user, such
as a web application or business application.

Data: Information created, processed, or stored by the application.

Identity & Directory Infrastructure: Systems that manage users,
accounts, authentication, and access permissions.

Accounts & Identities: Individual users, accounts, credentials, and
their permissions.

Devices: Physical devices such as laptops, desktops, and mobile phones
used by customers to access cloud services.


WHO MANAGES WHAT?
----------------------------------------
On-Premises:
Customer manages everything - physical datacenter, physical network,
physical hosts, network controls, OS, applications, data, identities,
and devices.

IaaS (Infrastructure as a Service):
Cloud provider manages Physical Datacenter + Physical Network +
Physical Hosts.
Network Controls: SHARED - the provider secures the underlying
network, but the customer still configures their own firewall
rules, NSGs (Network Security Groups), and network settings.
Customer manages OS + Applications + Data + Identities/Accounts +
Devices + (their part of) Network Controls.

PaaS (Platform as a Service):
Cloud provider manages Physical Datacenter + Physical Network +
Physical Hosts + OS.
Network Controls: still largely SHARED at this stage (e.g. with
Azure SQL, the customer configures allowed networks/firewall
rules, even though Microsoft manages the deeper infrastructure).
Customer manages Applications + Data + Identities/Accounts + Devices
+ (their part of) Network Controls.

SaaS (Software as a Service):
Cloud provider manages Physical Datacenter + Physical Network +
Physical Hosts + Network Controls + OS + Applications.
Customer manages Data + Identities/Accounts + Devices.

Correction/clarification: Network Controls is commonly shown as fully
"provider-managed" from IaaS onward in simplified charts, but in
Microsoft's official shared responsibility model it is a SHARED
responsibility in both IaaS and PaaS - the customer still configures
firewalls/NSGs/allowed networks themselves. It only becomes fully
provider-managed at the SaaS layer. This is a common point of
confusion, including on the AZ-900 exam.

One thing that never changes, in every model (even SaaS): the customer
always retains responsibility for Data, Accounts & Identities, and
Devices.


EASY RULE TO REMEMBER
----------------------------------------
On-Prem -> You manage everything.
IaaS -> Provider manages physical infrastructure; you manage OS and
        above (and share network configuration responsibility).
PaaS -> Provider manages infrastructure + OS; you manage application
        and above (and share network configuration responsibility).
SaaS -> Provider manages the application and everything below it; you
        mainly manage your data, identity/access, and devices.
